# Zotify MVP scope

Source: Hackathon problem statement #8, Spotify "language-steerable discovery".

## Goal

Type an intent ("something calm for a 3 a.m. study session"). Get a ranked list of tracks from a fixed catalog, each with a one-line explanation. A familiar / non-habitual switch changes how much the results lean on the user's listening history.

## In scope

1. **Catalog**: 20-50k tracks from a public dataset (Kaggle "Spotify tracks" with audio features, or Last.fm). Fields: title, artist, genre, tempo, energy, valence, acousticness, etc. No Spotify API, no audio.
2. **Item text and embedding**: build a short text per track (metadata plus audio features turned into words such as "low energy, acoustic, slow"). Embed with `sentence-transformers` (`all-MiniLM-L6-v2`).
3. **Semantic IDs**: residual quantisation (RQ) over the embeddings, 3 levels x 256 codes. Each track gets a tuple `(c1, c2, c3)`; resolve collisions with a 4th disambiguation code. Store a trie of all valid IDs.
4. **Intent to Semantic ID**: an LLM (Claude) turns the query into a short "ideal track" description. Embed it and decode a Semantic ID by beam search over the trie, level by level, scored against the codebooks (constrained decoding, so only real catalog items can come out).
5. **Familiar / non-habitual switch**: a mock user profile (a set of listened tracks, so a set of Semantic ID prefixes).
   - Familiar: boost candidates whose `(c1, c2)` prefix is in the profile.
   - Non-habitual: penalise those prefixes and boost candidates that are close to the query but in prefixes the user has never played.
   - One slider `lambda` in `[-1, 1]` drives the boost.
6. **Explanation**: Claude gets the query, the track metadata and the familiar/non-habitual label, and writes one sentence. Must only cite fields it was given.
7. **UI**: a Streamlit page with a query box, the slider and a results list.
8. **Eval** (small, scripted):
   - 50 synthetic queries, each generated by an LLM from a held-out track. Report recall@10 of the source track.
   - Novelty: share of results outside the profile prefixes at each slider end.
   - Explanation check: LLM-judge groundedness on 50 samples.

## Out of scope for the MVP

- Fine-tuning a generative model on Semantic IDs (this is what NEO does). Stretch goal: fine-tune a small seq2seq model such as T5-small on (query -> Semantic ID) pairs.
- Preference tuning from skip/save/replay (RLHF/DPO). Stretch goal: log slider and click feedback in the UI and show it.
- Real user accounts, audio playback, podcasts, multi-turn voice DJ.

## Honest gap to the source work

The MVP uses a pretrained embedder plus trie-constrained search. It does not learn to generate Semantic IDs end to end. Say so in the demo; the fine-tuned model is the first stretch goal.

## Layout

```
zotify/
  data/            catalog + mock profile
  build_catalog.py clean data, build item text
  embed.py         item embeddings
  semantic_ids.py  RQ codebooks, IDs, trie
  recommend.py     intent -> SID decode -> rerank with lambda
  explain.py       Claude explanation
  app.py           Streamlit UI
  eval.py          recall, novelty, groundedness
```

## Build order

1. `build_catalog.py` + `embed.py`: catalog loads, embeddings saved.
2. `semantic_ids.py`: IDs assigned, collision rate and codebook usage printed.
3. `recommend.py` with no LLM (query embedded directly): sanity-check results by hand.
4. Add the Claude intent step and `explain.py`.
5. Add the profile and the `lambda` switch; check novelty moves with the slider.
6. `app.py`, then `eval.py`.

## Open decisions

- Dataset choice (Kaggle Spotify tracks is the fastest start).
- LLM provider and key for intent and explanation (default: Claude API).
- Whether to take the Netflix #5 overlap as a second track later.
